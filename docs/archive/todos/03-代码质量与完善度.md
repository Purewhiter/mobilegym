# mobile-gym 代码质量与完善度深度分析

---

## 一、应用完整性问题

### 1.1 完全残缺的应用（无 manifest.ts）

- **`apps/12306/`** — 目录内仅有大量微信截图（`.jpg`），无任何代码文件
- **`apps/Douban/`** — 有 components/context/data/hooks/pages/services 目录，但无 manifest.ts、无入口 App 文件、未注册到 `os/types.ts`，完全孤立
- **`apps/XiaomiWeather/`** — 目录内仅有 `image/README` 文件

### 1.2 缺少 navigation.declaration.ts 的成熟应用

| 应用 | 已有页面数量 |
|---|---|
| `Calendar` | 10 个页面 |
| `Notes` | 7 个页面 |
| `Sms` | 多个 components 含页面 |
| `Weather` | 6+ 个页面 |
| `QQMusic` | 5 个页面 |
| `Browser` | 有 App 文件 |
| `Clock` | 有 App 文件 |
| `Gallery` | 大型单文件 |
| `ThemeStore` | 有 App 文件 |

**Settings 特例**：有 `navigation.declaration.ts` 但没有 `navigation.ts`，导致无 `go()`/`back()` 封装层。

### 1.3 缺少 types.ts 的应用

Calculator2、FileManager、Reddit、TencentMeeting、WechatReading

### 1.4 Camera 的 res/drawable/ 违规

`apps/Camera/res/` 下存在 `drawable/` 子目录（内含 `icons.tsx`），违反"res/ 下图标文件必须扁平放置"的规定。

## 二、导航规范违规

### 2.1 业务页面直接使用 useNavigate（严重违规）

**统计（页面文件，排除 NavigationHandler 和 App.tsx）：**

| 应用 | 违规文件数量 |
|---|---|
| `Calendar` | 10 个文件 |
| `Settings` | 9 个文件 |
| `Sms` | 9 个文件 |
| `Notes` | 8 个文件 |
| `Weather` | 6 个文件 |
| `Ebay` | 5 个文件 |
| `Wechat` | 3 个文件 |
| `TencentMeeting` | 3 个文件 |
| `Map` | 3 个文件 |
| **共计** | **约 59 个文件** |

### 2.2 Calendar 使用了非标准 back handler 名称（Bug）

`apps/Calendar/CalendarApp.tsx` 第 38 行：

```tsx
(window as any).__APP_STAY_BACK_HANDLER__ = handleBack;  // 错误
```

OS 只读取 `__APP_BACK_HANDLER__`，**从不读取** `__APP_STAY_BACK_HANDLER__`。Calendar 的系统返回键完全无效，是一个功能性 Bug。

### 2.3 NavigationHandler 代码大量重复

5 个独立的 NavigationHandler 文件几乎完全相同，核心逻辑逐字复制。应提取为 OS 层共享组件。

## 三、系统服务使用违规

### 3.1 直接使用 Date.now() / new Date()（应使用 TimeService）

违规文件超过 20 处，典型代表：

```
apps/Settings/context/SettingsContext.tsx:180     Date.now()
apps/Bilibili/pages/UserProfilePage.tsx:15        new Date()
apps/Calendar/context/CalendarContext.tsx:30      Date.now()
apps/Contacts/context/ContactsContext.tsx         Date.now() ×4
apps/WechatReading/context/WechatReadingContext.tsx  Date.now()
apps/Weather/utils/weatherStore.ts                Date.now()
apps/Gallery/GalleryApp.tsx:88                    Date.now()
```

### 3.2 Spotify 直接调用外部 fetch()（应使用 NetworkService）

5 处直接调用外部 API 的 raw fetch，会导致 CORS 错误：

```
apps/Spotify/pages/PlaylistPage.tsx:51
apps/Spotify/pages/ChooseArtistsPage.tsx:33
apps/Spotify/pages/LibraryPage.tsx:32,79
apps/Spotify/pages/ArtistPage.tsx:37
```

## 五、代码重复问题

### 5.1 Toast 组件被复制 6+ 次

完全相同的 Toast 实现分散在 Settings、Calendar、Sms、Contacts、Notes、FileManager，另有 TencentMeeting 两处内联定义。

### 5.2 safeParseJSON 在 5 个应用中独立实现

Settings、Contacts、Alipay、Wechat、Railway12306 各自实现。OS 自己（StatusBarService、NotificationService、DeviceService、QuickSettingsService）也各有一份。

### 5.3 大量字符串硬编码（不使用 res/strings.ts）

Bilibili 的 `res/strings.ts` 只有 16 个键，而页面中有 **884 处硬编码中文字符串**。

## 七、i18n 不完整性

### 7.1 Calculator2 英文翻译严重缺失

`strings.en.ts` 只有 3 个键，`strings.ts` 有 23 个键，**缺失 20 个键**。

### 7.2 Alipay 英文翻译缺 5 个键

缺少：`cashier_title`, `confirm_pay`, `order_info`, `pay_to_merchant`, `payment_amount`

### 7.3 Bilibili 几乎没有字符串资源

`res/strings.ts` 仅 16 个键（tab 名和商城分类），全部业务 UI 文本都是硬编码中文。

## 八、Agent 可观测性缺失

### 8.1 大量应用没有手势钩子（Gesture Hook）

没有 `use<App>Gestures.ts` 的应用：Calendar、Notes、Weather、Sms、QQMusic、Gallery、ThemeStore、Settings、Clock、Browser、Camera

### 8.2 多个应用完全没有 data-trigger 属性

- `Calendar` — 0 处（10 个页面！）
- `Notes` — 0 处（7 个页面）
- `Sms` — 0 处
- `QQMusic` — 0 处
- `Weather` — 0 处

Agent 无法观察到这些应用的任何导航动作。

## 十、测试覆盖与无障碍访问

### 10.1 零测试覆盖

整个 `apps/` 目录中没有任何测试文件。`package.json` 中没有 `test` 脚本，也没有引入 Vitest 或 Jest。

### 10.2 无障碍属性极度匮乏

全项目仅 **253 处** `aria-` 或 `role=` 属性。Wechat、Bilibili、Alipay、RedBook 等核心应用几乎没有 aria 标记。大量 `<div onClick>` 而非语义化的 `<button>`。

---

## 十一、其他边界违规

- Settings 所有业务页面直接 useNavigate（无 go() 封装）
- Spotify 数据加载器使用原生 fetch（而非 Vite import 或 NetworkService）
- Contacts 有非标准的 settings/ 子目录
