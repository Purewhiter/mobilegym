#导航图统一架构改进方案

> 优先级：**P0-P1**

> 预计总工时：3-5 天

> 目标：消除导航系统的多事实源问题，通过 codegen 让 `navigation.declaration.ts` 成为唯一事实源

---

##1. 问题诊断

###1.1 根本矛盾：三重事实源

路由信息存在于三个独立维护的位置，任何一个漏改就会不一致：

| 层 | 文件 | 说明 |

|----|------|------|

| 声明层 | `navigation.declaration.ts` | routes / transitions / actions 的完整描述 |

| 路由注册层 | `*App.tsx` 中的 `<Route>` | React Router 实际注册的路由 |

| 组件实现层 | `pages/*.tsx` 中的 `go()` / `bindTap()` | 运行时实际触发的跳转 |

当前的 consistency checker 只检查 **层1 vs 层3**（声明 vs 代码中的 go/bindTap 调用），完全跳过了 **层1 vs 层2**（声明 vs `<Route>` 注册）。

###1.2 P0 级问题清单

####P0-1：运行时导航语义碎片化

18 个 App 各自实现 `navigation.ts`，至少存在 4 种不同水平：

| 级别 | App | matchFrom | chooseCase | preserveParams | extractParamsFromPathTemplate |

|------|-----|-----------|------------|----------------|-------------------------------|

| 完整版 | Wechat, WechatReading, Alipay, Bilibili, RedBook, Reddit, X, Weather, FileManager, Contacts, Compass, Spotify | ✓ | ✓ | ✓ | 部分 |

| 简化版 | Map, Railway12306 | ✗ | ✗ | ✗ | ✗ |

| 最小版 | Settings | ✓ | ✗ | ✓ | ✗ |

| 异形版 | Ebay（`useEbayNavigation`）, Calculator2（路径模式） | ✗ | ✗ | ✗ | ✗ |

Ebay 的 `navigation.ts` 里写着：

```

// Simplified logic assuming simple transitions for now

// For a real robust implementation, we should copy the full logic from Wechat/navigation.ts

```

####P0-2：声明导出名不统一

Calculator2 用的是 `navigationDeclaration` + `appId`，导致生成器/检查器直接跳过它：

```typescript

// Calculator2

exportconstnavigationDeclaration = { appId: 'calculator2', ... }


// 其他所有 App

exportconstNAVIGATION_DECLARATION = { app: 'alipay', ... }

```

####P0-3：校验不是强门禁

-`build_nav_artifacts` 默认只跑 `--actions`，不带 `--fail-on-warn`

-`package.json` 没有 `nav:check` / `nav:build` 脚本入口

- 仓库内无 CI / pre-commit 配置

###1.3 P1 级问题清单

####P1-1：`navigation.types.ts` 在 18 个 App 中各有一份副本

且这 18 份**并不完全一致**：

| 差异点 | 涉及 App |

|--------|----------|

| `scrollContainers` 必选 vs 可选 | Alipay/Ebay/TencentMeeting 必选，其他可选 |

| `placement` 多了 `'drawer'` | Reddit, X |

| `StateCondition` 变体不同 | TencentMeeting 用 `equals/notEquals/empty`；Spotify 不同形状 |

| FileManager 是极简版 | 缺少 `CaseDeclaration`, `Condition`, `ValueRef` 等 |

| Calculator2 完全不同的类型 | 只有 `NavigateOptions` + `AppNavigateHook` |

| Railway12306 re-export Wechat | 已走在正确方向 |

####P1-2：检查器覆盖盲区

| 盲区 | 风险 |

|------|------|

| 声明 path vs `<Route>` 注册 path | 高 — 声明中多/少路由无法检测 |

| transition.to + search 是否对应有效 uiState | 高 — 边指向不存在节点 |

| searchParams key 是否在目标 queryParams 中声明 | 中 |

| manifest.intentFilters.route 与声明一致性 | 中 — deep link 漂移 |

| from.search 约束完整性（仅 best-effort warn） | 中 |

####P1-3：手势协议分叉

Ebay 的 `bindTap` 返回的 props 缺少 `data-trigger-type`，Calculator2 的 `bindBack` 只 stopPropagation 不执行返回。不是所有 App 都走 `useTriggerGestures`。

##2. 改进方案：分层递进式 Codegen

核心思路：**先收敛设计契约，再升级工具门禁，最终通过 codegen 消除多事实源。**

###2.1 全景路线图

```

S0（前置清理）       → S1（统一运行时内核）    → S2（codegen 三件套）

  ├ 修 Calculator2      ├ 提取共享内核              ├ 生成 navigation.generated.ts

  ├ 合并 types           ├ 18 个 App 接入            ├ 生成 gestures.generated.ts

  └ 加 npm scripts       └ 消灭所有简化版            └ 生成 routes.generated.tsx


→ S3（强门禁）          → S4（长期：声明即 App）

  ├ CI 必跑 nav:check      ├ 从 declaration 生成页面骨架

  ├ ESLint 禁直接导航       └ 从 declaration 生成完整 App 壳

  └ pre-commit hook

```

##3. S0：前置清理（0.5-1 天）

###3.1 Calculator2 导出名修复

**文件**：`apps/Calculator2/navigation.declaration.ts`

```typescript

// 前

exportconstnavigationDeclaration = {

  appId: 'calculator2'asconst,

...

}


// 后

exportconstNAVIGATION_DECLARATION = {

  app: 'calculator2',

...

} asconstsatisfiesNavigationDeclaration;

```

同步修改引用该导出的文件。

###3.2 合并 `navigation.types.ts` 为共享文件

**新文件**：`os/navigation.types.ts`（以 Wechat 版为基准的超集）

合并要点：

-`scrollContainers` 统一为**必选**（用 `[]` 表示"无滚动容器"，所有 App 的声明已遵守此模式）

-`placement` 加入 `'drawer'`（Reddit/X 需要）

-`StateCondition` 对齐到最完整版本（Wechat 版），TencentMeeting/Spotify 的变体需要迁移

- FileManager 的极简版补齐缺失类型（不影响其声明文件，因为类型是超集）
- Calculator2 的 `NavigateOptions` / `AppNavigateHook` 随 S1 合并到共享 runtime

18 个 App 全部改为：

```typescript

importtype { NavigationDeclaration, ... } from'../../os/navigation.types';

```

**风险点**：TencentMeeting 和 Spotify 的 `StateCondition` 字段名不同（`equals` vs `eq`），需要同步修改它们的 `navigation.declaration.ts` 中的实际用法。

###3.3 添加 npm scripts

```json

{

"scripts": {

"nav:check": "node scripts/check_all_navigation.mjs",

"nav:check:app": "node scripts/check_navigation_declaration_consistency.mjs",

"nav:build": "node scripts/build_nav_artifacts.mjs",

"nav:build:all": "node scripts/build_all_nav_artifacts.mjs"

  }

}

```

新增 `scripts/check_all_navigation.mjs`：自动发现所有含 `navigation.declaration.ts` 的 App 并批量检查。

##4. S1：统一运行时内核（1-1.5 天）

###4.1 提取共享导航内核

**新文件**：`os/navigation-runtime.ts`

从 Alipay/Bilibili 的完整实现中提取以下纯函数（无 React 依赖）：

```typescript

// os/navigation-runtime.ts


exportfunctionmatchFrom(from, pathname, searchParams):boolean { ... }

exportfunctionchooseCase(t, ctx):CaseDeclaration| null { ... }

exportfunctionbuildSearchParams(options):URLSearchParams { ... }

exportfunctionreplaceParams(path, params):string { ... }

exportfunctionextractParamsFromPathTemplate(template, pathname):Record<string, string> { ... }

exportfunctionmatchRoute(template, path):boolean { ... }

exportfunctionevalCondition(cond, ctx):boolean { ... }

exportfunctionresolveValue(ref, ctx):Primitive { ... }

```

**新文件**：`os/hooks/useNavigationRuntime.ts`

```typescript

import { useNavigate, useLocation, useSearchParams, useContext } from'react-router-dom';

import { UNSAFE_NavigationContext } from'react-router-dom';

importtype { NavigationDeclaration, TransitionDeclaration } from'../navigation.types';

import*asruntimefrom'../navigation-runtime';

import { memoryHistoryPopTo } from'../utils/memoryHistoryPopTo';


exportfunctionuseNavigationRuntime<

TIdextendsstring = string

>(declaration:NavigationDeclaration) {

constnavigate = useNavigate();

constlocation = useLocation();

const [searchParams] = useSearchParams();

const { navigator } = useContext(UNSAFE_NavigationContext);


constgo = (

    id:TId,

    params:Record<string, string|number> = {},

    options?: { mode?:'push'|'replace'; popTo?:string; popToInclusive?:boolean },

  ) => {

constt = declaration.transitions.find(x => x.id===id) asTransitionDeclaration| undefined;

if (!t) thrownewError(`Transition not found: ${id}`);


if (!runtime.matchFrom(t.from, location.pathname, searchParams)) {

thrownewError(`Transition "${id}" not allowed from "${location.pathname}${location.search}"`);

    }


constchosen = runtime.chooseCase(t, { pathname: location.pathname, searchParams, params });

consteffectiveTo = chosen? chosen.to: t.to;

consteffectiveSearch = chosen? chosen.search: t.search;

consteffectiveSearchParams = chosen?.searchParams|| t.searchParams;


constinheritedPathParams = runtime.extractParamsFromPathTemplate(effectiveTo, location.pathname);

constmergedParams = { ...inheritedPathParams, ...params };

consttargetPathname = runtime.replaceParams(effectiveTo, mergedParams);


constnewParams = runtime.buildSearchParams({

      currentSearchParams: searchParams,

      preserveParams: t.preserveParams|| [],

      staticSearch: effectiveSearch,

      dynamicSearchParams: effectiveSearchParams,

      runtimeParams: mergedParams,

    });


constsearchStr = newParams.toString();

consttargetUrl = searchStr?`${targetPathname}?${searchStr}`:targetPathname;


if (options?.popTo) {

memoryHistoryPopTo(navigator, options.popTo, { inclusive: options.popToInclusive });

    }

constmode = options?.mode?? t.mode;

navigate(targetUrl, mode==='replace'? { replace: true } :undefined);

  };


constback = (steps:number = 1) =>navigate(-steps);


return { go, back };

}

```

###4.2 各 App 接入

**12 个完整版 App**（零风险）：

各 App 的 `navigation.ts` 从 ~250 行简化为：

```typescript

import { useNavigationRuntime } from'../../os/hooks/useNavigationRuntime';

import { NAVIGATION_DECLARATION, typeTransitionId } from'./navigation.declaration';


exportfunctionuseAppNavigate() {

returnuseNavigationRuntime<TransitionId>(NAVIGATION_DECLARATION);

}

```

**4 个简化版 App**（需逐个验证）：

Map / Railway12306 / Settings 接入完整内核后，需要验证其 `navigation.declaration.ts` 的 `from` 约束是否正确。如果之前"因为没校验所以没报错"，切到完整版后会 throw，此时需修正 declaration。

**2 个异形版**（特殊处理）：

-**Ebay**：重命名 `useEbayNavigation` → `useAppNavigate`；替换自定义 `useEbayGestures` 为标准 gesture hook；补齐缺失的 `data-trigger-type`

-**Calculator2**：transitions 数组为空，`useNavigationRuntime` 的 `go()` 不会被调用；保留一个最小的 `useAppNavigate` wrapper 即可

###4.3 统一手势 hook

**目标**：让所有 App 的 gesture hook 结构一致。

当前 18 个 App 的 gesture hook（`use*Gestures.ts`）结构完全相同，唯一差异是 `TransitionId` 类型和 import 路径。统一后可以直接生成（S2 阶段），但 S1 先确保全部走标准 `useTriggerGestures`。

Ebay 的自定义 `bindTap` / `bindAction` / `bindBack` 需要替换为标准实现。

##5. S2：Codegen 三件套（2 天）

###5.1 codegen 脚本

**新文件**：`scripts/generate_navigation_code.mjs`

输入：`apps/<App>/navigation.declaration.ts`

输出：三个生成文件

###5.2 生成物 A：`navigation.generated.ts`

```typescript

// ============================================================

// 自动生成 — 不要手动编辑

// 来源: navigation.declaration.ts

// 生成命令: npm run nav:generate

// ============================================================

import { useNavigationRuntime } from'../../os/hooks/useNavigationRuntime';

import { NAVIGATION_DECLARATION } from'./navigation.declaration';


exporttypeTransitionId = (typeofNAVIGATION_DECLARATION.transitions)[number]['id'];


exportfunctionuseAppNavigate() {

returnuseNavigationRuntime<TransitionId>(NAVIGATION_DECLARATION);

}

```

替代手写的 `navigation.ts`（S1 完成后该文件已经很短，生成只是固化这个模式）。

###5.3 生成物 B：`gestures.generated.ts`

```typescript

// ============================================================

// 自动生成 — 不要手动编辑

// ============================================================

import { useTriggerGestures } from'../../os/hooks/useTriggerGestures';

importtype { TransitionId } from'./navigation.generated';

import { useAppNavigate } from'./navigation.generated';


typeSystemTriggerId = 'system.back';

typeGestureId = TransitionId|SystemTriggerId;


exportfunctionuseAlipayGestures() {

const { go, back } = useAppNavigate();

const { bindTap, bindLongPress, bindDoubleTap } = useTriggerGestures<GestureId>({

execute: (id, params) => {

if (id==='system.back') {

conststeps = Number(params?.steps) ||1;

back(steps);

return;

      }

go(id, params);

    },

  });


constbindBack = <TextendsHTMLElement>(options?: {

steps?:number;

stopPropagation?:boolean;

preventDefault?:boolean;

    [key:string]:any;

  }) => {

conststeps = options?.steps??1;

constbinding = bindTap<T>('system.back', { params: { steps }, ...options });

return { ...binding, 'data-trigger-type':'back'asconst };

  };


return { bindTap, bindLongPress, bindDoubleTap, bindBack, go, back };

}

```

hook 名称从 `NAVIGATION_DECLARATION.app` 推导（`alipay` → `useAlipayGestures`）。

###5.4 生成物 C：`routes.generated.tsx`


###5.5 codegen 工作流

```bash

# 生成单个 App

npmrunnav:generate--Alipay


# 生成所有 App

npmrunnav:generate:all


# 检查生成文件是否与 declaration 同步（CI 用）

npmrunnav:generate:check

```

`nav:generate:check` 运行 codegen 到临时目录，diff 已有生成文件，不一致则报错。

##6. S3：强门禁（1 天）

###6.1 CI 集成

```yaml

# .github/workflows/nav-check.yml

name: Navigation Consistency

on: [push, pull_request]

jobs:

check:

runs-on: ubuntu-latest

steps:

      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4

      - run: npm ci

      - run: npm run nav:generate:check# 生成文件是否同步

      - run: npm run nav:check# 声明一致性检查（全 App）

```

###6.2 ESLint 规则

`no-direct-navigate`：在 `apps/*/pages/**` 中禁止直接 `useNavigate()`，只允许 `useAppNavigate()`。

白名单：

-`os/**`（系统层允许）

-`apps/*/navigation.ts`（运行时 hook 内部允许，S2 后此文件为生成物）

-`apps/*/*App.tsx`（Router 注册处允许）

###6.3 pre-commit hook

如果修改了 `navigation.declaration.ts` 但没重新运行 `nav:generate`，阻断提交。

###6.4 检查器增强

在 `check_navigation_declaration_consistency.mjs` 中新增以下确定性检查（从 warn 升级为 error）：

| 新增检查 | 说明 |

|----------|------|

| Route 注册交叉验证 | 解析 `*App.tsx` 中的 `<Route>` AST，与 declaration.routes 比对 |

| Transition 目标可达性 | `to + search` 组合是否对应有效 uiState 节点 |

| manifest.intentFilters.route 一致性 | deep link 路由必须在 declaration.routes 和 Router 中都存在 |

| 禁止动态/非字面量 id | 对 `bindTap(variable)` 报 error（或要求 `as const` 的表驱动） |

##7. S4：长期愿景 — 声明即 App（持续推进）

S0-S3 完成后，`navigation.declaration.ts` 已成为事实上的唯一事实源。可以进一步延伸 codegen 的范围：

###7.1 生成页面骨架

```

navigation.declaration.ts

  → pages/HomePage.generated.tsx

      ├── 正确的 data-scroll-container 属性

      ├── 所有 actions 的 bindTap({kind:'action'}) 绑定占位

      ├── 通往其他页面的 transition 触发器占位

      └── useAppNavigationHandler 注册

```

开发者只需"填充业务 UI"，不需要关心导航声明同步。

###7.2 生成完整 App 壳

```

navigation.declaration.ts

  → App.generated.tsx

      ├── MemoryRouter + Routes（从 declaration 生成）

      ├── Layout + TabBar（从 entryPoint/tab transitions 推断）

      ├── NavigationHandler 注册

      └── 所有页面组件的 import + Route 注册

```

###7.3 与 Agent 训练的契合

当 declaration 成为唯一事实源后：

-**任务生成**：可以从图中精确生成端到端测试任务

-**App 生成**：可以先设计 declaration（定义 App 有哪些页面、状态、动作），然后生成完整骨架

-**一致性保证**：DOM 标签（data-trigger / data-action）与导航图中的节点/边严格对应，确保任务定义与轨迹合成的准确性

##8. 执行计划与风险

###8.1 执行计划

| 阶段 | 内容 | 工时 | 前置依赖 |

|------|------|------|----------|

| **S0** | Calculator2 修名 + 合并 types + npm scripts | 0.5-1d | 无 |

| **S1** | 提取 `os/navigation-runtime.ts` + 18 App 接入 | 1-1.5d | S0 |

| **S2** | codegen 脚本 + 生成三件套 | 2d | S1 |

| **S3** | CI + ESLint + 检查器增强 | 1d | S2 |

| **S4** | 页面骨架 / App 壳生成 | 持续 | S2 |

###8.2 风险矩阵

| 风险 | 概率 | 影响 | 缓解措施 |

|------|------|------|----------|

| 合并 types 时 StateCondition 变体不兼容 | 中 | 中 | 以 Wechat 版为基准做超集，逐个 App 迁移 |

| 简化版 App 接入完整内核后 from 校验 throw | 高 | 低 | 暴露的恰好是潜在 bug，修正 declaration 即可 |

| Ebay 自定义 gesture hook 替换影响 UI | 低 | 低 | Ebay 的自定义 hook 功能是标准 hook 的子集 |

| codegen 无法处理特殊 Layout 逻辑（Tab 常驻挂载） | 中 | 中 | routes.generated.tsx 只生成路由映射，Layout 逻辑仍手写 |

| 开发者绕过 codegen 直接修改生成文件 | 低 | 中 | CI 的 `nav:generate:check` 会检测到不同步 |

###8.3 不做的事（明确排除）

- 不改变 `navigation.declaration.ts` 的数据结构（声明格式本身是合理的）
- 不做运行时 codegen / HMR（生成物是静态文件，开发时需手动重新生成）
- 不在 S0-S3 阶段改变 `*App.tsx` 的 Layout 逻辑（Tab 常驻挂载等特殊模式保持手写）
- 不强制单页应用（Calculator2、Compass 等）采用完整 transition 机制
